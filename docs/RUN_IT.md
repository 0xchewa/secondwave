# Запуск и управление

## Первый запуск

Нужны Node.js 22.x (не ниже 22.12), npm и Git. На Windows рекомендуем Windows Terminal. Минимум 64×24 символа; от 120 столбцов список и карточка видны одновременно.

```sh
git clone https://github.com/0xchewa/secondwave.git
cd secondwave
npm ci
npm start
```

Вместо Git можно скачать Code → Download ZIP и открыть терминал в распакованной папке. `npm ci` устанавливает зависимости. Повторный запуск — только `npm start`.

Обычный запуск открывает **живой терминал**: сначала загружается локальное состояние, затем коллектор догоняет подтверждённый head и продолжает обновления. До этого видна метка CATCHING UP. Если данные отстают более чем на 90 секунд, текущая оценка Early скрывается.

Для полностью автономного просмотра включённой записи: `npm start -- --recorded`. В этом режиме сеть не используется, время и возраст токенов относятся к явно указанной дате записи.

## Клавиши

| Клавиши | Действие |
| --- | --- |
| 1 / 2 / 3 | Early Signal / Second Wave / сведения о моделях |
| ↑ / ↓, j / k, PgUp / PgDn | Навигация по всему локальному списку |
| / | Поиск по символу, названию или CA |
| s / f | Сортировка / фильтр |
| a | Переключить готовую выдачу и полный локальный каталог |
| h | Подготовить историю выбранного токена от launch; продолжить прерванную загрузку |
| w / c | Окно flow 5m / 1h / 24h и диапазон графика ALL / 1H / 4H / 24H |
| v | Факты запуска, creator history и подробные model explanations |
| m | Минимальная оценка Early: 0 / 1 / 2.5 / 5 / 10% |
| Enter / Esc | Карточка / назад |
| e | Экспорт выбранного токена и его расчётов в `.local` |
| l | Начать или повторить самостоятельный сбор |
| ? | Подсказки |
| q / Ctrl+C | Выход с сохранением уже завершённых страниц |

Цена `0.0{7}1234` означает семь нулей после десятичной точки до значащих цифр. Точное значение находится в JSON. ETH — единица котировки, а не доллары. График строится по минутным OHLCV с равномерной временной осью; пустые минуты не заполняются выдуманными сделками. `[h]` восстанавливает доступную историю от launch. Числа flow показываются только для подтверждённого полного интервала.

## RPC и ускорение через HyperSync

Скопируйте `.env.example` в `.env`. Укажите `SWAVE_RPC_URL`. Без настройки используется официальный публичный endpoint. URL с ключом провайдера не добавляйте в Git.

```dotenv
SWAVE_RPC_URL=https://rpc.mainnet.chain.robinhood.com
# Необязательно: собственный ключ Envio ускоряет чтение истории
ENVIO_API_TOKEN=
ENVIO_HYPERSYNC_URL=https://robinhood.hypersync.xyz
```

```sh
npm start
```

Нужна Robinhood Chain **mainnet 4663**. Консоль проверяет chain ID. Провайдер должен поддерживать чтение исторических logs, transactions, receipts и block headers; исторический `eth_call` нужен для деклараций миграции и reserve progress. HTTP разрешён только для localhost, внешние адреса — HTTPS. Отправка транзакций и подписи отсутствуют.

При наличии `ENVIO_API_TOKEN` автоматически используется HyperSync для событий и связанных транзакций, а RPC независимо проверяет границы блока и читает contract state. Без ключа работает обычный RPC. Можно явно выбрать `--transport rpc` или `--transport hypersync`. [Получение доступа и документация HyperSync](https://docs.envio.dev/docs/HyperSync/hypersync-quickstart).

Сбор продолжается с seed, затем с собственного checkpoint. Чем старше seed и ниже лимиты провайдера, тем дольше первый проход. Полная история не обещается мгновенно. Коллектор оставляет 20 блоков подтверждений, сохраняет каждую завершённую страницу и соблюдает ошибки лимитов провайдера.

Конечный проход и просмотр его результата:

```sh
npm start -- sync --pages 2 --blocks 1000
npm start -- snapshot --state .local/checkpoint.json.gz --mode wave
npm start -- inspect 0xYOUR_CONTRACT --state .local/checkpoint.json.gz
```

`--pages`: 1–1000, `--blocks`: 1–10000. По умолчанию страница RPC — 1000 блоков, HyperSync — 6000. Snapshot и inspect читают сохранённое состояние без сети.

### Старый контракт и полная история

```sh
npm start -- lookup 0xYOUR_CONTRACT --transport hypersync
npm start -- hydrate 0xYOUR_CONTRACT --pages 100
npm start -- inspect 0xYOUR_CONTRACT
```

Поиск с HyperSync проверяет factory events от genesis. Для RPC укажите `--from-block` около запуска: диапазон ограничен 200 000 блоков. В интерактивном режиме введите полный CA через `/`, затем нажмите `h`. Готовый контракт сохраняется в каталоге; повторный `hydrate` продолжит незавершённую работу. Приоритет интерактивного сборщика — живой head, история готовится страницами после него.

Если у старого контракта нет сохранённого launch-time Early vector, текущими счётчиками он не заменяется. Wave можно восстановить из проверенной истории миграции независимо. Для токенов без проверенного pool история Wave остаётся недоступной с конкретной причиной.

После обновления со старого выпуска можно начать с нового seed, сохранив прежнее состояние: `npm start -- --state .local/terminal-v2.json.gz`.

## Перенос записи

```sh
npm start -- export --state .local/checkpoint.json.gz --output .local/session.json.gz
npm start -- --input .local/session.json.gz
npm start -- snapshot --mode early --json
```

`--input` открывает датированную запись в режиме RECORDED. Полный checkpoint для продолжения RPC также содержит causal counters; перенос одного session-файла их не заменяет. Не сочетайте `--input`, `--recorded` и `--live`.

## Ошибки и восстановление

- **401/403:** проверить ключ и разрешения RPC; завершённый checkpoint остаётся.
- **429 / timeout:** desk повторяет попытку с паузой, сохраняя checkpoint; конечную CLI-команду можно запустить повторно. В момент отставания более 90 секунд Early estimate приостанавливается. Собственные лимиты RPC и HyperSync важны для свежести.
- **REORG / ARCHIVE UNAVAILABLE:** проверить исторический доступ и block hash через доверенного провайдера. Для реального reorg нужен checkpoint до расхождения или новый проверенный seed. Автоматического перескока поверх расхождения нет.
- **LOCAL_STATE_LOCKED:** проверьте PID в соседнем `.lock`. Если процесс действительно завершился аварийно, удалите только этот lock-файл и запустите снова. Не удаляйте блокировку работающего сборщика.
- **Недостаточная история:** это состояние покрытия, а не низкая оценка токена. Прочитайте причину в карточке и [границы сборщика](DATA_SOURCES.md).

Проверки: `npm run check`, `npm run build`, `npm test`, `npm run bench`. Для запуска скомпилированной версии после сборки: `node dist/cli.js`.
